Why does hierarchy work?
• Temporal locality
   − Recently executed insns likely to be executed again
      • Inner loops
   − Recently referenced data is likely to be referenced again soon
      • Data in inner loops, hot global data
   − Hierarchy is reactive: move things up when accessed


• Spatial locality
   − Insns near recently executed insns likely to be executed soon
       • Sequential execution
   − Data near recently referenced data likely to be referenced soon
       • Elements in an array, fields in a struct, variables in frame
   − Hierarchy can be proactive: move things up speculatively

Calculating Tag Overhead
• 32KB cache means cache holds 32KB of data
   − Called capacity
   − Tag storage is considered overhead


• Tag overhead of 32KB cache with 1024 32B frames
   − 32B frames ® 5-bit offset
   − 1024 frames ® 10-bit index
   − 32-bit address – 5-bit offset – 10-bit index = 17-bit tag
   − (17-bit tag + 1-bit valid)* 1024 frames = 18Kb tags = 2.2KB tags
   − ~6% overhead

   1. Remembers miss address
   2. Accesses next level of memory for data
   3. Waits for response from next level
   4. Upon receiving response
      • Fills cache:
           • Writes data/tag into proper location in cache

Block Size and Tag Overhead
• Tag overhead of 32KB cache with 1024 32B frames
   − 32B frames ® 5-bit offset
   − 1024 frames ® 10-bit index
   − 32-bit address – 5-bit offset – 10-bit index = 17-bit tag
   − (17-bit tag + 1-bit valid) * 1024 frames = 18Kb tags = 2.2KB tags
   − ~6% overhead ((2.2KB/32KB) * 100)


• Tag overhead of 32KB cache with 512 64B frames
   − 64B frames ® 6-bit offset
   − 512 frames ® 9-bit index
   − 32-bit address – 6-bit offset – 9-bit index = 17-bit tag
   − (17-bit tag + 1-bit valid) * 512 frames = 9Kb tags = 1.1KB tags
   + ~3% overhead ((1.1KB/32KB )* 100)

Block Size and Miss Penalty
• Does increasing block size increase tmiss?
   − Don’t larger blocks take longer to read, transfer, and fill?
   − They do, but…


• tmiss of an isolated miss is not affected
   − Critical Word First
   − Requested word fetched first, pipeline restarts immediately
   − Remaining words in block transferred/filled in the background


• tmisses of a cluster of misses will suffer
   − Reads/transfers/fills of two misses can’t happen at the same time
   − Latencies can start to pile up
   − But, this is a bandwidth problem

Replacement Policies
• Set-associative caches present a new design choice
   − On cache miss, which block in set to replace (kick out)?
• Some options
   − Random
   − FIFO (first-in first-out)
      • Does not match temporal locality
          • Loops w/ same mem location accessed continuously
   − LRU (least recently used)
      • Fits with temporal locality, LRU = least likely to be used in future
   − NMRU (not most recently used)
      • An easier to implement approximation of LRU
      • Note: NMRU is LRU for 2-way set-associative caches
   − Belady’s: replace block that will be used furthest in future
      • Unachievable optimum (used for comparison)

                                                                      43
LRU Algorithm
• Determines which cache block has been used least-
  recently

• Cache monitors the usage of cache blocks:
   − Aging using age counts associated with each cache block
   − For a 4-way set-associative-mapped cache, two bits of additional
     storage can be used to monitor the age of each cache block in a
     set
   − When a cache block in a set is used / replaced, its age is
     reset and all other ages lower than the previous age are
     incremented


• LRU leverages temporal locality

Classifying Misses: 3C Model
• Divide cache misses into three categories
   − Compulsory (cold): never seen this address before
      • Startup

   − Capacity: miss caused because cache is too small
      • Consecutive accesses to block separated by access to at least N
        other distinct blocks (N is number of frames in cache)

   − Conflict: miss caused because cache associativity is too low
      • All other misses

   − (Coherence): miss due to external invalidations
      • Only in shared memory multiprocessors (later)

Write Propagation
• When to propagate new value to (lower level) memory?

• Option #1: Write-through: immediately
   − Immediately send the write to the next level
   + Conceptually simple
   + Uniform latency on misses
      + Dirty/clean miss: 1 transaction (write next level)
   – Requires additional bus bandwidth




                                                             61
Write Propagation
• When to propagate new value to (lower level) memory?

• Option #2: Writeback: when block is replaced
   − Requires additional “dirty” bit per block
      + Minimal bus bandwidth
          • Only write back dirty blocks
      – Non-uniform miss latency
          • Clean miss: 1 transaction (fill)
          • Dirty miss: 2 transactions (writeback & fill)




                                                            62
Write Miss Handling
• How is a write miss actually handled?

• Write-allocate: fill block from next level, then write value
  into it
   + Decreases read misses (next read to same block will hit)
   – Requires additional bandwidth
   − Used with writeback caches


• Write-not-allocate: just write to next level, no allocate
   – Potentially more read misses
   + Uses less bandwidth
   − Used with write-through

Split vs. Unified Caches
• Split I$/D$: insns and data in different caches
   − To minimize structural hazards and thit
   − Larger unified I$/D$ would be slow, 2nd port even slower


• Unified L2, L3: insns and data together
   − To minimize %miss
   + Fewer capacity misses: unused insn capacity can be used for data
   – More conflict misses: insn/data conflicts
      • A much smaller effect in large caches
   − What about simultaneous I$ and D$ misses?
      • Quite rare

Summary
• Average access time of a memory component
   − latencyavg = latencyhit + %miss * latencymiss
   − Hard to get low latencyhit and %miss in one structure ® hierarchy
• Memory hierarchy
   − Cache (SRAM) ® memory (DRAM) ® swap (Disk)
   − Smaller, faster, more expensive ® bigger, slower, cheaper
• Cache ABCs (capacity, associativity, block size)
   − 3C miss model: compulsory, capacity, conflict
• Performance optimizations
   − %miss: prefetching
   − latencymiss: victim buffer, critical-word-first
• Write issues
   − Write-back vs. write-through/write-allocate vs. write-not-allocate
